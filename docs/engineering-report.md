# Docker pull timeout engineering report

The first-pull delay was reproduced in the code path used by production: `dispatch()` awaited `Mirror.blob()`, which queued the transfer, downloaded the entire blob, fsynced it, verified SHA-256, committed CAS content and repository metadata, and only then returned to `writeHead()`. HEAD followed the same body-download path. Background multi-platform archival shared that semaphore, including with cache hits. A 30-second Docker response-header deadline could therefore expire during a healthy large download; a retry benefited from the completed cache or retained partial file. The upstream transport also imposed an absolute 120-second transfer timer, interrupting healthy longer transfers. Production hosts and logs were not accessed; the cause and fix are verified with local HTTP integration fixtures.

Cache misses now confirm upstream status and essential metadata before explicitly flushing response headers. One digest-scoped transfer writes the temporary file with disk backpressure. Concurrent clients independently tail written offsets through bounded 64 KiB chunks and HTTP pipeline backpressure. Disk provides the shared spool, letting slow/disconnected clients release their readers without cancelling archival or delaying other clients. This follows the blob, HEAD and range behavior described by the [Docker Registry API](https://github.com/distribution/distribution/blob/main/docs/content/spec/api.md) and [OCI Distribution specification](https://github.com/opencontainers/distribution-spec/blob/main/spec.md); it is not a claim of full OCI conformance.

Integrity remains mandatory. `Store.commitFile()` still hashes the entire file, validates its size and durably publishes immutable CAS content. Public provenance and source repository membership follow verified publication. Every live full or range response withholds its final byte until that succeeds. Failure after headers destroys the response short of Content-Length; failure before headers retains a structured registry error. Incomplete transfers remain temporary for later Range resume; digest/size failures discard the temporary file. Empty responses wait for verification because they have no final byte to retain. Bytes streamed before completion are provisional and clients must verify their requested digest. Private CAS possession alone still grants no public access; cross-repository reuse and shared transfers retain upstream permission checks.

Content-Length derives from verified manifest descriptors and must match any advertised upstream length. Resume Content-Range, status, digest headers and content encoding are validated before success. Client single/suffix ranges, clamping, 206/416, If-Range and HEAD remain supported. HEAD misses validate upstream metadata without downloading or publishing a blob. Interrupted streams abort attached clients; later pulls or persistent archive jobs resume rather than replaying a started response. Existing crash recovery and corrupt-content replacement continue to pass.

Separate manifest/blob schedulers retain bounded queues and single flights, promote requested queued downloads, and reserve two additional foreground slots by default. The existing six-slot background limit remains configurable. Client manifests and blobs can progress while other architectures archive asynchronously. Cache-hit blobs and HEAD avoid the blob queue. A full background queue cannot consume foreground queue capacity. Overloaded foreground blob waits return bounded 503 responses.

New environment settings separate DNS/TCP/TLS connection timeout (5 seconds), per-hop response headers (10 seconds), the total header/authentication/redirect/retry budget (25 seconds), and idle reads (120 seconds). Two additional attempts use exponential backoff starting at 250 ms and capped at 2 seconds. Only transient connection and selected upstream 5xx failures are retried before streaming, including transient token-service errors. Confirmed absence, denied authentication, policy/integrity errors and 429 are not retried; Retry-After/cooldown remain intact. `UPSTREAM_TIMEOUT_SECONDS` remains accepted as the default idle-read timeout. Active body transfers may outlive the header budget. SSRF allowlists, redirect validation, DNS pinning, anonymous permission proof, local repository authorization and archival publication rules remain in force.

`blob_request` and `blob_download` structured events record digest/provider, cache outcome, queue wait, upstream response-header latency including retries/authentication, emitted/downloaded bytes, total/active download duration, retries, failure codes and client disconnects. Aggregate byte, retry and disconnect counters remain available through protected metrics. URLs, tokens and authorization headers are excluded.

The Nginx example already disabled buffering and had a 900-second read timeout. That timeout does not change Docker's own header deadline. It now explicitly disables inherited proxy caching, response compression and upstream replay. Deployment documentation covers one PM2 fork process, environment reload, Nginx validation, and matching the backend port to `.env` (`5000` in the proxy example; `5007` in the CI health-check default). No production deployment or Nginx reload was performed.

Verification on November 19, 2026 (Node.js v24.22.0): `npm test` passed **126 tests with zero failures, skips or cancellations** in 42.9 seconds. The 31-second transfer received response headers in **54 ms** and completed verified delivery in 31,086 ms. The targeted streaming/security/recovery run also passed 62 tests. All 31 JavaScript files passed syntax checks, runtime imports remained built-in/relative with no npm dependencies, and `git diff --check` passed. Tests include a real 31-second upstream body with an independent 30-second client header timer, concurrent full/range pulls, HEAD, transient/exhausted failures, resumed/ignored ranges, chunked/empty bodies, malformed metadata, upstream/disk integrity failures, disconnects before and after headers, a paused client, foreground scheduling, and separate connection/header/idle/authentication deadlines. All prior security, Push, offline, synchronization and real SIGKILL recovery tests are included. The implementation remains native Node.js ESM with zero runtime dependencies.

Nginx and Docker executables are unavailable locally, so live Docker-through-Nginx qualification remains a deployment check. Local tests demonstrate that the mirror no longer makes the Docker header wait depend on an upstream blob's complete transfer duration; they cannot make an unavailable upstream produce valid headers.
